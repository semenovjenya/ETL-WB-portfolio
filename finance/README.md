# Модуль сбора финансовых отчетов Wildberries

Модуль для автоматического сбора финансовых отчетов через API метод `POST /api/v5/supplier/reportDetailByPeriod` с инкрементальной загрузкой по дням, начиная с 29 января 2024 года.

## Возможности

- Инкрементальная загрузка данных по дням
- Автоматическое сохранение прогресса в БД и файл
- Обработка ошибок и retry логика
- Rate limiting для соблюдения лимитов API
- Интеграция с Apache Airflow
- Сохранение данных в PostgreSQL и JSON файлы

## Установка

1. Установите зависимости:

```bash
pip install -r requirements.txt
```

2. Настройте переменные окружения. Создайте файл `.env` в корне проекта или скопируйте `env.example`:

```bash
# API Wildberries
WB_API_TOKEN=your_wildberries_api_token

# PostgreSQL
DB_HOST=localhost
DB_PORT=5432
DB_NAME=your_database_name
DB_USER=your_database_user
DB_PASSWORD=your_database_password
```

## Использование

### Базовое использование (инкрементальная загрузка)

```bash
python fetch_report_detail.py
```

При первом запуске скрипт начнет сбор данных с 29 января 2024 года. При последующих запусках будут загружаться только новые дни (начиная с последней обработанной даты).

### Полная перезагрузка

Для выполнения полной перезагрузки всех данных:

```bash
python fetch_report_detail.py --full
```

### Указание диапазона дат

```bash
python fetch_report_detail.py --start-date 2024-01-29 --end-date 2024-02-05
```

Таблица для хранения прогресса инкрементальной загрузки:

- `last_processed_date` (DATE) - последняя обработанная дата
- `updated_at` (TIMESTAMP) - время обновления

## Логика инкрементальной загрузки

1. **При первом запуске**: начинается с 29 января 2024 года
2. **При последующих запусках**:
   - Загружается последняя обработанная дата из БД (приоритет) или файла
   - Обрабатываются дни от (последняя дата + 1 день) до (сегодня - 1 день)
   - Прогресс сохраняется после каждого успешного дня
3. **При ошибке**: прогресс не обновляется, данные будут повторно обработаны при следующем запуске

## Интеграция с Airflow

DAG `wb_report_detail_daily` настроен на ежедневный запуск в 3:00 утра.

### Задачи DAG:

1. **check_progress** - проверка текущего прогресса
2. **fetch_report_data** - получение данных за недостающие дни
3. **update_progress** - обновление прогресса

### Настройка DAG:

DAG автоматически создает таблицы при первом запуске и обрабатывает только новые дни.

## Обработка ошибок

- Автоматические повторные попытки при сетевых ошибках (3 попытки)
- Обработка 429 (Too Many Requests) с экспоненциальной задержкой
- Логирование всех операций и ошибок
- Graceful shutdown при критических ошибках
- Сохранение частично полученных данных

## Rate Limiting

Модуль соблюдает лимиты API Wildberries:
- Интервал между запросами: 20 секунд (лимит API: 3 запроса в минуту)
- При получении 429 (Too Many Requests) - автоматическое увеличение задержки

## Примечания

- API Wildberries имеет лимиты на количество запросов (3 запроса в минуту)
- Данные за сегодня могут быть неполными, поэтому по умолчанию обрабатываются данные до вчерашнего дня
- Рекомендуется запускать скрипт в нерабочее время для полной выгрузки
- Инкрементальная загрузка более эффективна и рекомендуется для регулярных обновлений
- Убедитесь, что база данных PostgreSQL доступна и имеет достаточно места для хранения данных

## Оценка времени и места

Для периода с 29 января 2024 года:

- **Время сбора**: 6-9 часов (при стабильной работе)
- **Место на диске**: 
  - Малый продавец (100 операций/день): ~50-100 МБ
  - Средний продавец (500 операций/день): ~250-500 МБ
  - Крупный продавец (2000+ операций/день): ~1-2 ГБ

**Примечание:** Детальная структура данных (каждая операция отдельной записью) требует больше места, чем агрегированные данные, но предоставляет полную информацию для анализа.
