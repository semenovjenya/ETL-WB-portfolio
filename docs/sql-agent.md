# SQL-агент над данными ETL

SQL-агент добавлен в связанный backend как потребитель данных платформы. Основа — официальный LangGraph SQL workflow: стандартные граф, сообщения, инструменты и tool calls. Каталог и защищённый исполнитель адаптированы к данным проекта.

В этом публичном репозитории находится описание интеграции. Исполняемый код агента остаётся в отдельном приватном backend; инструкции ETL не являются инструкциями запуска агента.

## Вопрос пользователя

Например:

> Как изменились заказы и рекламные клики SKU DEMO-001 за 2026-10-26 — 2026-11-01 по сравнению с предыдущим периодом?

Это пример интерфейса, а не результат выполненного теста. Пользователю не требуется указывать имена таблиц, CTE, JOIN или готовый SQL. Модель должна выбрать источники по каталогу и уточнить их схему.

Текущий вход требует один явно обозначенный SKU и один диапазон дат в формате `ГГГГ-ММ-ДД — ГГГГ-ММ-ДД`, не длиннее 31 дня. Сравнение выполняется с предыдущим периодом той же длины. Формулировка «за прошлую неделю» без точных дат приводит к запросу уточнения.

## Цикл исследования

1. **Вопрос и доступ.** Backend определяет подключение, права и параметры разрешённой проверки.
2. **Выбор источников.** Модель получает короткий список доступных таблиц с описаниями.
3. **Уточнение схемы.** Инструмент возвращает поля и особенности выбранных источников. Предусмотрено ограниченное повторное уточнение схемы.
4. **Генерация и проверка.** Модель составляет SQL и проверяет его перед передачей исполнителю.
5. **Выполнение.** Исполнитель проверяет policy и лимиты, затем читает PostgreSQL ограниченной ролью. Ошибка может привести к исправлению SQL в пределах бюджета.
6. **Результат.** Возвращаются колонки, строки, сведения о покрытии/происхождении и ограничения.
7. **Вывод.** Доменный агент использует результат для ответа или пересмотра гипотезы. Недостаток данных остаётся явным.

Во вложенном режиме SQL-подграф завершается на результате: отдельный вызов модели для его пересказа не нужен. Вывод принадлежит вызывающему доменному агенту. В standalone-режиме можно отдельно запросить текстовый ответ SQL-агента.

## Каталог и ограничения

Каталог описывает доступные объекты конкретного окружения; детали загружаются по выбранным источникам. Состав рабочей БД не обязан совпадать с пустой базой, развёрнутой из портфолио.

- Только разрешённые чтения; DML/DDL из модельного SQL не выполняются.
- Подключение, роли и учёт бюджета принадлежат серверу.
- Ограничиваются время выполнения, объём данных, попытки SQL и модельные обращения.
- Native-профили сохраняют проверенные SKU/period scopes. Общие исследовательские источники не получают эти гарантии автоматически.
- NULL, ноль, отсутствие загрузки и неизвестное происхождение различаются.
- JOIN может размножать строки; доступность синтаксиса не доказывает корректность агрегации.
- Производный SQL-результат не становится автоматически канонической финансовой метрикой или доказательством причины.
- Успех чтения, доставка результата модели и принятие вывода проверяются отдельно.

Поиск по API-документации через pgvector — другой компонент: он возвращает текст о методах API. SQL-агент получает бизнес-строки из PostgreSQL. Добавление SQL-агента не заменяет существующий поиск по документации.

## Статус и проверки

Состояние на 9 ноября 2026 года. Следующие результаты относятся к рабочему backend, а не к тестам этого публичного checkout.

| Проверка | Подтверждённый результат | Граница вывода |
| --- | --- | --- |
| Отдельный SQL-агент с реальной моделью и БД | В одном прогоне модель написала SQL, получила 14 строк и сформировала ответ; строки совпали с контрольным SQL | Вопрос задавал способ агрегации/соединения. Это не проверка самостоятельного выбора способа запроса без подсказок |
| Упрощение runtime | Локальные проверки SQL, scope, replay, consumer integration и совместимости контрактов прошли | Локальные проверки не заменяют live-приёмку |
| Короткий каталог и schema по запросу | Подключены к runtime и проверены локально | Качество самостоятельного выбора источников реальной моделью требует отдельной приёмки |
| Полный цикл свободной гипотезы через доменного агента | Live-приёмка ещё не пройдена: наблюдались отказы валидации ответов и ошибки провайдера | Успешный отдельный SQL-прогон не закрывает этот сценарий |
| Повторный реальный цикл после упрощения | Остановился на первом запросе к модели из-за недоступного API-баланса | Новая успешная цепочка вопрос → SQL → результат → вывод не подтверждена |
| Публичное воспроизводимое демо | Пока не включено | Этот репозиторий не запускает backend SQL-агента |

Это сводка результатов разработки; рабочие журналы, бизнес-строки и credentials не публикуются в портфолио. Часть данных рабочей проверки могла иметь replay/неизвестное происхождение. Технический успех запроса не доказывает достоверность причинного бизнес-вывода.

## Следующий шаг для портфолио

Добавить отдельный воспроизводимый пример на синтетическом датасете, переиспользующий рабочий SQL-компонент и его ограничения. Для такого демо нужны:

- минимальные данные и ожидаемый результат контрольного запроса;
- обычный вопрос без имён таблиц и подсказок про SQL-конструкции;
- документированные зависимости и команда запуска;
- проверка вопрос → выбранная схема → SQL → строки → вывод;
- отдельные тесты запрета записи и ограничений доступа;
- явное разделение offline/scripted проверки и платного live-прогона.

Пример не должен включать весь приватный backend или создавать второй самописный агентский runtime.
